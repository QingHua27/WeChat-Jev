## 验收目标

- 每条对方文本气泡下独立浅灰卡片，随消息正常排版、滚动；自己的回复不增加分析卡片。
- `Jev:` 标题，黑色紧凑正文，分段问题、Yes/No、意图和行动百分比、风险与建议。卡片内容随语境变化，不能把参考图百分比硬编码为真实结果。
- Jev 概率使用 `probabilities` / `noul`，不能把 `confidence` 当候选概率。缺失或非法数值不伪造。
- 历史消息判断只使用该条及之前的上下文，避免后文泄漏。
- 已解决的判断停止后续解释/回复生成；新对方消息可重新判断。
- 生命周期、重复消息、IPC兼容与异常输入有回归验证。

## 本轮实现与验证

- 只将对方普通文本作为分析目标。自己发送的内容仅可作为目标之前的上下文；采集、调度和显示层均排除自己的分析卡片。图片、语音、通话记录不生成卡片。
- 使用真实 Jev 分布生成分段问题、Yes/No、意图、行动、风险和建议；强“已解决”判断跳过后续解释及回复生成。未配置模型时明确标注本地演示。
- 浅灰卡片直接插在微信文本节点下方，无固定高度截断；保留微信消息原有布局参数。匹配支持微信自定义文本 View，取消猜测消息位置的回退。
- 修复列表复用后重复挂载导致的崩溃、新消息取消上一条分析、长文本误判发送方向、键盘弹出后识别失败，以及卡片布局触发零距离滚动事件导致的重复模型调用。
- 真实滚动会取消当前视口计算并重新识别可见消息，但保留已经挂在消息行上的卡片，避免滑屏时瞬间消失；本地 `msgId` 用作稳定卡片 ID，避免相同文本在不同位置错贴。通话时长、未应答、对方已取消等微信系统行会被统一过滤。
- 通过新的只读 IPC 从当前微信会话的 `message` 表按联系人读取完整本地文本记录，采用 `msgId/createTime` 游标分页；自己的消息保留为上下文，目标仍只选对方消息。读取失败、会话切换、快照变化或撤回均停止该次分析，不降级成可见片段。
- 微信撤回系统提示、撤回消息类型及本地撤回边界都会被过滤；撤回事件主动清除现有卡片和待处理分析。

## 当前边界

- 微信导航、气泡、头像、输入栏及深浅主题使用手机原生显示；没有将整页变成参考图中的 iOS 微信。
- 进入聊天后从微信本地记录按新到旧补齐所有对方文本消息；滑动时只恢复当前消息行的卡片，缓存命中不调用模型，未完成队列在切换聊天或关闭该会话后停止，下次进入从缓存继续。结果按稳定 `msgId` 匹配，重复文本不会错贴。
- 本地记录读取依赖微信 8.0.72 的当前进程、WCDB 和 `Chat_User` 会话标识；不支持的微信版本会停止分析并记录原因。
- 本轮新分段内容用于实时卡片，尚未扩展主 App 历史数据库保存这些分段字段。
- 真机验收覆盖当前设备与微信版本，未声称所有微信版本或整页像素完全一致。
